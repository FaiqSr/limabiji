# B2B Landing Page — Implementation Plan

> **For Hermes:** Use this plan to implement the B2B landing page task-by-task. Each task is bite-sized (2–5 min). Follow the plan's exact file paths, code snippets, and commands.

**Goal:** Add a high-conversion B2B landing page with lead capture form to the existing Lima Biji Agritech Laravel application, 100% consistent with the existing Design System, Blade component architecture, and backend conventions.

**Architecture:** Pure Blade + Tailwind CSS v4 + daisyUI v5. No new JS framework. A new `b2b_leads` database table, a `B2BLead` Eloquent model, a `B2BLeadController` following the existing `LandingPages` controller pattern, a new `B2BLeadFormRequest` for validation, and a new Blade view `landingpages.b2b` that extends the existing `layouts.landingpages` layout. Form submission uses standard HTTP POST with server-side redirect — no AJAX at this stage to keep scope minimal.

**Tech Stack:** Laravel 13.8, PHP 8.3, Tailwind CSS v4.3.3, daisyUI v5.7.16, Motion.js, SQLite, Blade

### TASK 3: Create Form Request Validation

**Objective:** Create a dedicated Form Request class for B2B lead validation.

**Files:**
- Create: `app/Http/Requests/B2BLeadFormRequest.php`

**Step 1: Generate form request**

```bash
php artisan make:request B2BLeadFormRequest
```

**Step 2: Write validation rules**

```php
<?php

namespace App\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;

class B2BLeadFormRequest extends FormRequest
{
    public function authorize(): bool
    {
        return true;
    }

    public function rules(): array
    {
        return [
            'name'           => ['required', 'string', 'max:255'],
            'email'          => ['required', 'email', 'max:255', 'unique:b2b_leads,email'],
            'company_name'   => ['required', 'string', 'max:255'],
            'team_size'      => ['nullable', 'string', 'in:1-10,11-50,51-200,201+'],
            'phone'          => ['nullable', 'string', 'max:50'],
            'business_needs' => ['nullable', 'string', 'max:2000'],
        ];
    }

    public function messages(): array
    {
        return [
            'email.unique' => 'This email has already submitted a request. Our team will contact you shortly.',
        ];
    }
}
```

**Verification:** `php artisan tinker --execute="echo class_exists(App\Http\Requests\B2BLeadFormRequest::class) ? 'OK' : 'FAIL';"`

### TASK 4: Create B2BLeadController

**Objective:** Create a controller with `show` (display form page) and `store` (process submission) methods, following the `LandingPages` controller pattern.

**Files:**
- Create: `app/Http/Controllers/B2BLeadController.php`

**Step 1: Write controller**

```php
<?php

namespace App\Http\Controllers;

use App\Http\Requests\B2BLeadFormRequest;
use App\Models\B2BLead;
use Illuminate\Http\RedirectResponse;
use Illuminate\View\View;

class B2BLeadController extends Controller
{
    public function show(): View
    {
        return view('landingpages.b2b');
    }

    public function store(B2BLeadFormRequest $request): RedirectResponse
    {
        B2BLead::create($request->validated());

        return redirect()
            ->route('landingpages.b2b')
            ->with('success', 'Thank you! Our sales team will contact you within 24 hours.');
    }
}
```

## RISKS, TRADEOFFS & OPEN QUESTIONS

### Risks
1. **No email notification yet** — The current plan stores leads in DB but doesn't send email/Slack notifications. This is deliberate (YAGNI) — the admin can check the DB directly. Notification can be added in a follow-up task.
2. **No CAPTCHA / spam protection** — For production, consider adding a honeypot field or Laravel's built-in rate limiting.
3. **No admin panel** — Leads are viewable only via `php artisan tinker` or a DB browser. An admin interface is a separate scope.

### Tradeoffs
1. **Server-side form submission** with full page redirect (not AJAX) — simpler, consistent with the existing codebase which has no JS framework. AJAX can be added later.
2. **Hardcoded data** in Blade views (testimonials, features, logos) — follows the exact pattern already used in `index.blade.php`, `news.blade.php`, etc. Can be migrated to DB later.
3. **No email verification** — B2B leads don't require email verification. The `email` field is validated for format and uniqueness but not confirmed.

### Open Questions
1. Should the B2B page be linked from the main homepage CTA section? (Currently the CTA says "Get Samples & Quote" → `#`)
2. Should we add a notification email to `export@limabijiagritech.com` when a new lead is submitted?
3. Should the "Contact" link in the navbar now point to the B2B page instead of `#`?
